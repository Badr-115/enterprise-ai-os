# Architecture and engineering decisions

## System boundary

The browser sends typed requests to the same-origin `/api/*` path. Next.js proxies these requests to FastAPI. FastAPI validates request shapes, stores data in SQLite, and calls deterministic pandas-based analytics. The workflow coordinates a bounded set of read-only tools and creates a report whose numeric claims are checked against computed KPI values. Gemini is an optional narrative provider and is not a source of truth for numeric claims.

## ADR-001: deterministic arithmetic, optional language generation

**Decision:** financial metrics, grouping totals, quality findings, and verification are computed in Python. The language model may summarize supplied facts but does not own calculations.

**Reason:** an interview demo should make it possible to trace a result back to its source and reproduce the arithmetic. This design reduces, but does not eliminate, the risk of misleading output.

**Trade-off:** deterministic intent matching supports a narrower set of requests than a general autonomous planner. Unsupported operations must be stated honestly instead of silently guessed.

## ADR-002: explicit read-only tool registry

The allowlist in `backend/app/agents/tools.py` exposes:

- `dataset_profile`: source metadata and quality counts.
- `profitability_check`: validated revenue, cost, margin, and margin-rate values.
- `quality_audit`: structured quality issue summary.
- `anomaly_review`: detected outliers, labeled as review signals rather than proof.
- `category_breakdown`: revenue aggregation by an available categorical column.

Selection uses transparent keyword/intent rules. Each result records success, a short explanation, elapsed time, and JSON-serializable output. Tools do not accept shell commands, SQL, arbitrary Python, or paths from the prompt. The registry is intentionally bounded and read-only.

## ADR-003: keep evidence and limitations in the report

Findings reference deterministic fields or quality signals. Reports include limitations, including that outliers are not proof of fraud and uploaded rows may not represent all company activity. These are part of the product contract, not optional UI copy.

## Current constraints

- SQLite targets a single-instance demonstration.
- Authentication, authorization, tenant isolation, and production data retention are not implemented.
- Tool selection is rule-based; it is not yet autonomous model-driven planning.
- Frontend browser/e2e tests and production deployment verification remain separate release gates.

## Extending the registry safely

1. Add a small, deterministic, read-only function to `tools.py`.
2. Return a `ToolResult` with a clear success flag, summary, and bounded JSON payload.
3. Add explicit intent selection; never execute tool names or arguments generated by a model without schema validation and policy checks.
4. Add unit tests for normal, empty, invalid, and adversarial prompt cases.
5. Add an integration test proving the API response preserves the tool trace.
6. Update this document and the interview demo runbook.
